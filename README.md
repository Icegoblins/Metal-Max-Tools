# METAL MAX Database & BS 控制器 — 项目说明

重装机兵2 Reloaded（MM2R）资料站 + 交互式地图（BS 控制器）。站点本身是纯静态前端（`dist/`）+ Python 数据转换脚本，无后端、无第三方前端依赖。桌面版工具箱见第 7 节。

---

## 1. 目录结构

```

├── dist/                       # 站点根目录（所有静态资源，可直接部署）
│   ├── index.html              # 主站：数据资料库 + 音乐点唱机
│   ├── map.html                # BS 控制器：交互式地图（单图/瓦片双模式）
│   ├── app.html                # 旧版入口（保留）

├── 战车数据转换.py             # 旧版战车数据转换（已被通用转换覆盖，保留备用）
```

## 2. 快速开始

```bash
# 安装依赖（建议用 .venv）

# 本地预览（必须走 HTTP，直接双击 html 会因浏览器限制读不到 data/*.json）
```

## 3. 数据维护流水线（数据侧）

### 3.1 分类数据：`通用转换.py`

- 数据源：当前目录的 `mm2r_database.xlsx`，**一个工作表 = 一个前端分类 = 一个 JSON**。
- 直接运行 `python 通用转换.py`，输出到 `dist/data/<工作表名>.json`。
- 自动跳过 `Sheet*`、名称含「隐藏」、`战车装备` 开头的分表工作表；`链装词缀库` 不单独出文件，并入 `链装.json`。
- **链装合并规则**：词缀按分类整池挂载（嵌能=人类链装、相阵=战车链装，每件链装显示词缀库中该分类的全部词缀）；词缀数值显示为 `+最小值~最大值`（**最小值=随机基础值，最大值=强化满级后的值**，如 `火焰伤害 +5%~15%`）；若行内填了 `词缀1~4` 则只显示填写的词缀（覆盖整池）；「链装强化」表按名称并入每条记录的 `强化数据`（强化等级 → 词条1~3，前提是名称与链装表一致）。词缀库中的重复行自动去重，链装表整行为空的行自动过滤；词缀库的 `+1/+2/+3` 列已废弃不读。
- **新增一个分类**：在 xlsx 里加一张工作表（表头第一行）→ 跑脚本 → 在 `dist/config.json` 数组里加上同名条目（页签顺序 = 数组顺序）→ 完成。

### 3.2 链装表结构：`添加链装表.py`

往主 xlsx 写入链装系统 4 张工作表（链装 / 链装套装 / 链装强化 / 链装词缀库）的表头与示例行，结构说明见该文件 docstring。主文件被 Excel 占用时输出 `链装_模板.xlsx` 供手工复制。

### 3.3 点唱机：`扫描歌曲.py`

- 把音频文件放进 `dist/music/` → 运行 `python 扫描歌曲.py` → 生成 `dist/data/点唱机.json`。
- 分组规则在 `dist/music/song_groups.json`（首次运行自动生成模板）：`rules` 按顺序批量匹配（prefix/contains/regex），`songs` 单曲精确指定，优先级高于规则。改完重新跑脚本即可。
- 歌曲配图无；播放、收藏、批量分组均在前端完成，收藏存 localStorage。

### 3.4 条目配图约定

把图片放到 `dist/img/<分类名>/<条目名>.png`（也支持 jpg/webp，按此顺序探测），前端详情页自动加载；没有图显示 NO_SIGNAL。分类专属背景图：`dist/img/<分类名>_bg.png`，存在即生效（映射表见 index.html 里 `CAT_BG_MAP`）。

## 4. BS 控制器（map.html）使用要点

### 4.1 数据文件格式

**`data/地图.json`** —— 地图册注册表（数组，一项一张地图，下拉框顺序 = 数组顺序）：

```json
[
  { "id": "world", "名称": "世界地图", "图片": "img/地图/world.png" },
  { "id": "world2", "名称": "大地图(瓦片)", "瓦片": "img/地图/tiles/world2", "宽": 16384, "高": 8192 }
]
```

- 单图模式：只需要 `图片`。安全上限约 8192×8192（浏览器需整图解码，极限 16384）。
- 瓦片模式：`瓦片` + `宽` + `高`（原图像素尺寸）。**支持任意大的图**，只加载视野内的瓦片。
- `id` 是点位数据的键，确定后不要再改。

**`data/地图点位.json`** —— 预设点位，按地图 id 分组，坐标 = 原图像素坐标：

```json
{
  "world": [
    {
      "名称": "某洞穴入口",
      "类型": "入口",
      "x": 9778,
      "y": 17477,
      "区域": { "x": 9760, "y": 17450, "宽": 64, "高": 80 },
      "跳转": { "地图": "D01某洞穴", "x": 1200, "y": 900, "缩放": 1.5 },
      "备注": "洞口"
    }
  ],
  "D01某洞穴": [
    {
      "名称": "出口",
      "类型": "出口",
      "x": 1200,
      "y": 900,
      "跳转": { "地图": "world", "x": 9778, "y": 17477 }
    }
  ]
}
```

- `类型` 可选：城镇 / 道具 / 隐藏道具 / 赏金首 / 特殊 / 事件 / **入口** / **出口** / 其他（图标与颜色定义在 map.html 顶部，可改可加；旧数据的 `BOSS` 自动并入 `赏金首`、`宝箱` 自动改名 `道具`）。
- `图片` 可选：配图（如 BOSS 立绘），点击点位在信息卡中显示，支持透明 PNG / JPG / WebP / GIF。
- **`跳转`**（可选）：`地图` = 目标地图 `id`（须在 `地图.json` 登记）；`x`/`y` = 落地镜头中心；`缩放` 可选。
- **`区域`**（可选）：矩形热区（地图像素坐标），用于洞口等可点区域；与标记配合使用。编辑模式可「在图上框选热区」。
- **`分组一级` / `分组二级` / `分组三级`**（可选）：点位与**绘制区域**共用；标记列表与全局搜索的分组。留空则点位按「地图→类型→名称」（或当前地图「类型→首字→名称」），区域按「地图→区域→名称」（或当前地图「区域→首字→名称」）。
- **`data/地图区域.json`**：按地图 id 分组的闭合区域（名称需与怪物「出没地点」一致时可从主站点击跳转）；结构与编辑模式导出的区域相同，可含分组字段。
- **地图跳转操作**：点击入口/热区 → 信息卡「进入」；**Shift+点击** 直接跳转；顶栏 **◀ 返回** 或 **Esc**（无弹窗时）回到上一张图。手动切换顶栏地图会清空返回栈。

### 4.2 两种角色、两种模式

| 模式 | 入口 | 用途 | 数据保存位置 |
|---|---|---|---|
| 标记模式 | 顶栏「标记模式」 | 用户自由标记/标注/点位记录 | **工具箱 exe**：程序旁 `用户数据/地图标记.json`（含附图）；**浏览器**：localStorage（可导出/导入 JSON 分享） |
| 编辑模式 | 顶栏「编辑模式」 | 数据侧维护预设点位 | localStorage 草稿 → 「导出点位JSON」下载 → 覆盖 `data/地图点位.json` 正式发布 |

**编辑模式工作流**：进入编辑模式 → 点击地图落点（或点击已有点位编辑/拖动）→ 填名称/类型/备注/图片/跳转与热区 → 「导出点位JSON」→ 用下载文件覆盖 `data/地图点位.json`。放弃改动用「放弃本次草稿」。

**用户标记**：标记模式下点击地图落点；标记可拖动微调；可附带本地图片（选图后自动压缩成 dataURL，透明 PNG 保留，≤150KB 原样保存含 GIF 动图，大图压到 420px）；左面板可导出/导入/清空。数据按地图 id 分开保存，换地图互不影响。

- **桌面工具箱**：标记和附图写到 exe 同目录的 `用户数据/地图标记.json`，不受浏览器 localStorage 约 5MB 限制。换电脑把 **exe + `用户数据` 文件夹** 一起拷走即可。
- **浏览器预览**：仍走 localStorage；附图存满会弹窗提示，重要标记请导出。

### 4.3 操作与快捷键

- 拖拽平移；滚轮以光标为中心缩放；双击复位；触屏双指缩放。
- 快捷键：`+` / `-` 缩放，`0` 复位适应窗口，`Esc` 关闭弹窗/退出模式。
- 顶栏按钮：图例面板开关、像素网格开关（256px 一格，辅助写坐标）。
- 坐标读取：鼠标移动时底部状态栏实时显示原图像素坐标，写点位数据照抄即可。
- 图例点击类型可过滤显隐，`我的标记` 行控制用户标记显隐。
- 左侧面板 **[ 标记列表 ]**：三级树形浏览（当前地图 / 全部地图），点位与绘制区域一起列出；点击点位定位至 100%，点击区域 `fit` 到范围；顶栏搜索框（`Ctrl+K`）全局搜点位与区域。
- 主站 `globalSearchAndJump`：wiki 未命中时会查 `地图点位.json` 并跳转 BS 地图；怪物/赏金首「出没地点」标签调用 `globalMapJump` 优先匹配 `地图区域.json`。

**地图绘制区域**（顶栏「区域」）：在图上画多边形/矩形，可加选/减选并合并。名称默认显示在区域**中心**，白字、区域色描边（无色块标签）。

- 侧栏 **[ 区域 ]** 列表旁的 **用户 / 预设** 表示数据来源，**不是**分组名：用户 = 本地绘制（localStorage）；预设 = `地图区域.json` 或编辑草稿。
- 弹窗或右键「分组」可填 `分组一级/二级/三级`；侧栏区域列表按分组树展示。
- 点击区域弹窗或右键菜单的「文本」：九宫格位置（`nw/n/ne/w/center/e/sw/s/se`）与可选**固定字号**（屏幕像素，不随缩放）。
- 右键顶栏「区域」：全局默认（基准字号、最小/最大屏幕字号、描边）。缩小地图字号会升到上限，放大则降到下限。
- JSON 字段（用户数据 / 导出的 `区域`）：`标签位置`（默认 `center`）、`标签字号`（省略则跟随全局缩放夹紧）、`分组一级/二级/三级`（可选）。

### 4.4 大地图制作流程：截图 → 拼接 → 切片

**拼接工作台**为 PyQt6 桌面程序（不依赖浏览器），与第 7 节的 Tauri 工具箱 exe **相互独立**——做地图时单独分发 `拼接工作台.exe` 即可。

#### 运行（开发）

```powershell
# 项目根目录，建议 .venv
pip install -r requirements.txt   # 含 opencv-python、PyQt6

python 拼接工作台.py 截图目录
# 不带参数时启动后在顶栏选目录
```

#### 打包（发布 exe）

目标：生成 `工具箱打包/拼接工作台.exe`（单文件、无控制台，体积约 80–120MB；对方机器**不需要**装 Python）。

```powershell
# 项目根目录，首次先装依赖
pip install -r requirements.txt pyinstaller

# 一键打包（推荐，不用记 PyInstaller 参数）
python 打包拼接工作台.py
```

产物：`工具箱打包/拼接工作台.exe`。双击运行；可把 exe 拷到任意目录，通过顶栏打开截图文件夹。`build/工作台/` 是临时文件，可删。

#### 工作台功能

- **打开目录**：弹出文件夹选择，导入截图到左侧素材库（不自动拼接）。有 `拼接工作台.json`（或更完整的 `.bak`）时恢复已置入位置。导出的大图（如 `MAP.png`、`拼接结果.png`）**不会**再被当成截图导入。
- **刷新**：重新加载当前路径下的截图与会话。
- **目录监控**：打开目录后自动监视文件夹，新截图会出现在图层列表（**不自动置入**）。
- **截图图层**：紧凑列表；**空格**或右键「预览大图」可查看原图；双击置入/移出。
- **置入画布**：双击未置入图，或点「置入画布」。第一张作为拼图起点。
- **锚点对应**（单张快速）：
  - 未置入图：画布框选已有地貌 → 弹出新图再框同一块 → 置入；
  - 已在画布上：连续框两处相同地貌 → 立即移动单张对齐。
- **对应拼接**（多图批量）：先把多张图粗略置入画布 → 交替框选参照区与对应区（须在不同截图上）→ 点「**执行对齐**」一次性按多对区域对齐。
- **移动**：点击选中**连通组**（**Alt+点击**=只选单张）；图层独立放在无限画布上，拖动只移动选中图；开吸附时**边缘靠近网格线**才会贴齐（白色网格）；**方向键**±1px 不吸附；拖空白或中键平移画布。**撤销 / Ctrl+Z**。
- **修正取样**：框选区域 → 侧栏列出覆盖该区域的源图 → 点击盖章贴回；
- **去除**：框选要去掉的对象 → 自动从其它截图中挑选最干净的一帧真实像素盖章覆盖；不满意可点侧栏候选换帧；
- **画布网格**：顶栏可开关网格（白色）、设置间距（1–512px，默认 64）、独立开关「吸附」（拖动时边缘靠近网格才贴齐）；状态栏显示像素坐标与格坐标；
- **瓦片库**：「存为瓦片」框选画布区域保存到 `瓦片库/`；「贴瓦片」从库中选取后点击画布放置（作为补丁覆盖，可撤销）；
- 图层列表右键仍可「自动拟合此图」（模板匹配，失败可改用锚点）；
- 会话保存在截图目录的 `拼接工作台.json`，覆盖前若旧点位更多会备份为 `拼接工作台.json.bak`；
- 「导出」成品 PNG → `地图切片.py` 切瓦片上站。

操作：滚轮缩放，拖画布平移（左键在查看模式，或中键）；对应区域列表、补丁列表右键可删除。

命令行方式（不需要预览修正时）：`python 截图拼接.py 截图目录 -o 大地图.png`（需 opencv-python）。

### 4.5 地图登记：`地图切片.py`

傻瓜窗口（双击或无参数运行）或命令行，自动写入 `data/地图.json`，不用手改 JSON。

**单图模式**（洞穴等小图，边长 ≤8192 时 GUI 会自动推荐）：

```bash
python 地图切片.py 洞穴.png --single
python 地图切片.py 洞穴.png --mode single --id D01洞穴 --name 某洞穴
```

- 复制到 `dist/img/地图/<id>.<ext>`，登记 `图片` 字段；原图可在任意目录。

**瓦片模式**（世界大地图）：

```bash
python 地图切片.py 大地图.png
python 地图切片.py 大地图.png -o dist/img/地图/tiles/world
# 可选：--format png（无损，默认 jpg q88）
```

- 自动生成多级缩放瓦片金字塔（512px/块，LANCZOS 缩放），登记 `瓦片` + `宽` + `高`。
- **输出目录名 / id = 地图 id**，请与点位数据的键保持一致。
- 后续扩图：替换大图重跑脚本即可，点位坐标（原图像素）不用改。
- 同一 id 从瓦片改单图（或反过来）会覆盖 `地图.json` 中对应字段，旧瓦片目录不会自动删除。

## 5. 主站前端（index.html）开发要点

- **页签**：由 `config.json` 驱动；窗口放不下自动折叠进 `[More]`（`refitTabs()`，resize 时重算）。
- **分类渲染插件**：`js/pages/*.js` 通过 `window.registerPageRenderer(分类名, { renderStats, onUpdateVisual, skin? })` 注册，`showDetail()` 统一调用。新增分类一般只需要：xlsx 加表 → 跑脚本 → config.json 加页签 → 需要特殊详情样式时写一个渲染插件。
- **全局弹窗**：用站内统一的 `mmAlert(msg, 'warning')` / `mmPrompt(msg, 默认值, onOk)` / `mmConfirm(msg, onOk)`，不要用浏览器原生 alert/prompt。
- **跨分类跳转**：`window.globalSearchAndJump('条目名')` 全库精确→模糊搜索并高亮定位；详情里可放 `onclick="globalSearchAndJump('掉落物名')"` 实现联动。
- **点唱机**是特殊布局（隐藏图片区），逻辑在 `js/pages/dianchangji.js`，列表渲染走 `renderMusicData` + 收藏置顶分组。

## 6. 注意事项 / 已知坑

- **必须 HTTP 访问**：浏览器里 `fetch('data/*.json')` 在 file:// 协议下会被拦截。已打包的工具箱 exe 不需要另开 HTTP（资源已内嵌）。
- **文件名大小写与中文路径**：图片路径完全按名称匹配，部署到 Linux 时注意大小写。
- **标记存储**：浏览器键 `mm2r_map_user_marks_v1`、编辑草稿 `mm2r_map_admin_draft_v1`；工具箱 exe 另将「我的标记」同步到 `用户数据/地图标记.json`。清浏览器数据只影响浏览器预览，不影响 exe 旁的用户数据文件。
- **点位坐标体系**：始终是原图左上角为原点的像素坐标，单图/瓦片模式通用；换更高清底图后按比例缩放 x/y 即可。

## 7. 桌面工具箱（mm2r-toolbox）

Tauri 窗口壳，前端仍是 `dist/`。没有独立后端 API；列表/详情都是读 `dist/data/*.json`。拼接工作台是独立 Python 工具，**不并入**本 exe；打包见 **§4.4 打包**。

站点前端一直可以用第 2 节的 Python HTTP 在浏览器里改。开发模式：窗口直接加载当前 `dist/`，改完刷新即可，不必为 HTML/CSS/JS/JSON 重编 Rust。

### 开发

```powershell
cd mm2r-toolbox
npm run dev
```

会由 exe 内置静态服务 `http://127.0.0.1:18765` 提供 `dist/`（数据缓存优先）。改 `dist/` 后**刷新窗口**即可。改 `src-tauri` 里的 Rust 仍要等编译。

首次需要在该目录执行过 `npm install`（已有 `package.json`，CLI 为 `@tauri-apps/cli`）。

### 远程数据热更新（GitHub Pages + Releases）

桌面 exe 可从 GitHub 拉取最新游戏数据到 exe 旁的 `数据缓存/`，**不必为改 JSON/图片/音乐而重打包 exe**。

1. 编辑 `dist/data-remote.json`：填写 `pagesBase`、`githubRepo`，设 `enabled: true`
2. 维护数据后：

```powershell
python 通用转换.py
python 扫描歌曲.py          # 音乐有变时
python 地图切片.py          # 地图有变时
python 生成数据清单.py      # → dist/manifest.json

git add dist/data dist/img dist/manifest.json dist/config.json ...
git commit -m "data: 更新"
git push                    # → GitHub Actions 部署到 Pages

python 发布数据.py --release   # 仅 music/ 有变：打 music.zip 并 gh release
python 生成数据清单.py         # 更新 manifest 中 music.zip 的 hash 后再 push
```

3. 用户端：标题栏状态区点 **SYNC**，或启动后自动后台同步（已启用时）

**托管分工**：Pages = `manifest.json` + `data/` + `img/` + `config.json`；Releases = `music.zip`（音频+封面）。

仓库需在 GitHub 开启 **Pages**（Source: GitHub Actions）。公开仓库即可，无需 Token。

### 打包发布

**默认（瘦客户端）**：exe 只内嵌界面，不含 `data/` `img/` `music/`；首次运行需联网并从 GitHub 同步到 `数据缓存/`（请先配置 `dist/data-remote.json`）。

```powershell
cd mm2r-toolbox
npm run build:exe
```

`beforeBuildCommand` 会自动跑 `准备瘦客户端dist.py` 生成 `dist-shell/` 再编译。产物约几十 MB。

**完整离线包**（内嵌全部 dist，约 300MB+，不依赖远程）：

```powershell
cd mm2r-toolbox
npm run build:exe:full
```

产物：`mm2r-toolbox/src-tauri/target/release/METAL MAX 工具箱.exe`。目标机器需 **WebView2**（Win10/11 通常自带）。

瘦客户端分发时建议同时说明：需配置 GitHub Pages 地址，或预先拷贝一份 `数据缓存/` 目录。

需要 NSIS 安装程序时：

```powershell
cd mm2r-toolbox
npm run build
```

安装包在 `src-tauri/target/release/bundle/nsis/`。

用户标记：首次保存后，exe 同目录出现 `用户数据/地图标记.json`。分发或换电脑时拷走 exe 与该文件夹。
