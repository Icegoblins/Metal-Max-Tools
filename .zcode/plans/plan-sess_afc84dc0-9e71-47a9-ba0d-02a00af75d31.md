## 「去除」功能重做（拼接工作台）

### 交互（前端，PAGE 内 JS）
1. 「去除」按钮进入去除模式，状态栏分步提示：
   - **去除①：框选要去除的对象**（小框，如战车/主角本体）
   - **去除②：框选计算区域**（包含对象及其周边，用于多帧检测计算）
2. 第二步框选完成 → `POST /api/erase {target, region}` → toast 显示计算方式（多帧投票去除 / 静止对象图像修复）→ 刷新预览。
3. Esc 取消当前步骤；补丁列表显示「去除」补丁，可单独删除回退。
4. 清理上一版"背景填充"半成品（WB.erase 平铺填充版、旧 /api/erase 参数、说明文案）。

### 计算逻辑（后端 Workbench.erase(target, region)）
坐标转世界坐标后：
1. 收集所有覆盖 region 的已放置源帧，构建区域像素栈（NaN 填充未覆盖处）；
2. **多帧投票**：每像素
   - 覆盖 ≥3 帧 → 取中位数（会动的主角/战车在帧间位置不同，投票后自动消失）；
   - 覆盖 2 帧 → 两帧相同则保留，不同保留当前画面（无法判定）；
3. **静止对象检测**：比较投票结果与当前画面在 target 框内的差异
   - 差异明显 → 对象帧间移动过，投票已将其去除；
   - 差异很小 → 对象在所有帧里都静止 → 对 target 框（外扩 2px 蒙版）执行 `cv2.inpaint`（TELEA 算法）用周边背景推算填充；像素风纹理会有涂抹感，界面提示可再用「修正取样」精修；
4. 计算出的区域图像以 base64 存为补丁 `{kind:"erase", x,y,w,h, data}`，composite 时解码叠加（内存缓存解码结果避免重复解码）；随会话 JSON 持久化，可单独删除。

### 验证
1. **离线测试**：用拼接结果当地图，程序化走两步流程——
   - 场景 A：主角在三帧位置不同 → 框选目标+区域 → 多帧投票后消失；
   - 场景 B：静止战车（每帧同位置）→ 投票无法消除 → 自动走 inpaint 修复；
2. **浏览器实测**：重启工作台，界面走一遍两步框选流程 + 补丁删除 + 会话恢复。
3. 更新 README 4.4 节工作台说明。
